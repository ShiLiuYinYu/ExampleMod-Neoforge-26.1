# 架构规范

> NeoForge 26.1 模组项目架构规范

---

## 包名规范

- **反向域名**：`com.<团队名>.<modid>`
- **全部小写**，不含大写字母
- `modid` 必须与包名中的模组段一致，且满足正则 `[a-z][a-z0-9_]{1,63}`

---

## 模块划分

```
<mod_group_id>
├── .                     ← 根包：主类、配置、数据生成入口
├── block/                ← 方块：注册中心 + 自定义方块类
├── item/                 ← 物品：注册中心 + 材料/食物/工具定义 + 自定义物品类
├── entity/               ← 实体：注册中心 + 属性 + 生物类 + 生成器
├── client/               ← 客户端专属：模型 + 渲染器
├── datagen/              ← 数据生成器（全部以 Provider 结尾）
├── tag/                  ← 标签常量定义
└── util/                 ← 工具/辅助类
```

### 各模块职责

| 模块 | 职责 | 典型类 |
|------|------|--------|
| 根包 | 模组入口、配置、总线注册 | `<ModMain>`、`<ModMain>Client`、`<ModMain>DataGenerator`、`Config` |
| `block/` | 方块声明与自定义方块逻辑 | `ModBlocks`、`custom/*` |
| `item/` | 物品/工具/盔甲/食物的注册与属性 | `ModItems`、`ModCreativeModeTabs`、`ModFoods`、材料类 |
| `entity/` | 实体类型注册、AI/属性/生成 | `ModEntities`、`ModEntityAttributes`、`<生物分类>/*`、`spawner/*` |
| `client/` | 仅客户端代码（`@Mod(dist = Dist.CLIENT)`） | 模型 LayerDefinition、EntityRenderer |
| `datagen/` | 数据生成 Provider | 所有 `Mod*Provider` 类 |
| `tag/` | 标签 Key 常量 | `ModBlockTags`、`ModItemTags` |
| `util/` | 可复用的辅助逻辑 | 工具类、效果类等 |

## 注册模式

### DeferredRegister 模式（NeoForge 标准）

所有注册对象使用 `DeferredRegister` + `DeferredHolder` 模式，在 `@Mod` 主类构造方法中统一注册到 Mod 事件总线：

```java
// 1. 在注册中心类中定义 DeferredRegister 和 DeferredHolder 常量
public class ModItems {
    public static final DeferredRegister.Items ITEMS =
            DeferredRegister.createItems(<ModMain>.MOD_ID);
    public static final DeferredItem<Item> EXAMPLE_ITEM =
            ITEMS.registerSimpleItem("example_item");

    public static void register(IEventBus eventBus) {
        ITEMS.register(eventBus);
    }
}

// 2. 在 @Mod 主类构造方法中调用注册
public <ModMain>(IEventBus modEventBus, ModContainer modContainer) {
    ModItems.register(modEventBus);
    ModBlocks.register(modEventBus);
    ModEntities.register(modEventBus);
    ModCreativeModeTabs.register(modEventBus);
}
```

### 注册对象类型对照

| 注册对象 | 注册器类型 | 注册中心类 | 注册表 |
|---------|-----------|-----------|--------|
| 物品 | `DeferredRegister.Items` | `ModItems` | `BuiltInRegistries.ITEM` |
| 方块 | `DeferredRegister.Blocks` | `ModBlocks` | `BuiltInRegistries.BLOCK` |
| 实体 | `DeferredRegister<EntityType<?>>` | `ModEntities` | `Registries.ENTITY_TYPE` |
| 创造模式物品栏 | `DeferredRegister<CreativeModeTab>` | `ModCreativeModeTabs` | `Registries.CREATIVE_MODE_TAB` |

## 事件总线体系

NeoForge 有两级事件总线，按用途选择：

| 总线 | 获取方式 | 用途 | 示例 |
|------|---------|------|------|
| **Mod 总线** | `@Mod` 构造方法参数 `IEventBus` | 注册、初始化 | `FMLCommonSetupEvent`、注册 DeferredRegister |
| **Game 总线** | `NeoForge.EVENT_BUS` | 游戏运行时事件 | `ServerStartingEvent`、`ModifyCustomSpawnersEvent` |

### 事件订阅方式

1. **构造方法中注册**（适用于 `@Mod` 主类自己的方法）：
   ```java
   modEventBus.addListener(this::commonSetup);
   ```

2. **`@EventBusSubscriber` 注解**（适用于独立类的静态方法）：
   ```java
   @EventBusSubscriber(modid = <ModMain>.MOD_ID)
   public class SomeHandler {
       @SubscribeEvent
       public static void onEvent(SomeEvent event) { ... }
   }
   ```

3. **显式注册到 Game 总线**（适用于 Mod 总线外的运行时事件）：
   ```java
   NeoForge.EVENT_BUS.register(this);
   NeoForge.EVENT_BUS.addListener(SomeHandler::onEvent);
   ```

## 客户端分离

- 客户端专属代码放在 `client/` 包下
- 客户端入口类使用 `@Mod(value = MOD_ID, dist = Dist.CLIENT)` 注解
- 服务端不可用的类（如 `Minecraft`、`EntityRenderer`）**绝不**出现在通用代码路径中

```java
@Mod(value = <ModMain>.MOD_ID, dist = Dist.CLIENT)
@EventBusSubscriber(modid = <ModMain>.MOD_ID, value = Dist.CLIENT)
public class <ModMain>Client {
    // 渲染器注册、模型层注册等
}
```

## 数据生成器规范

- 所有数据生成类放在 `datagen/` 包，以 `Provider` 结尾
- 统一在 `<ModMain>DataGenerator.gatherData()` 中通过 `GatherDataEvent.Client` 注册
- 生成输出目录：`src/generated/resources/`（通过 `build.gradle` 的 `runData` 配置指定 `--output`）

```java
@EventBusSubscriber(modid = <ModMain>.MOD_ID)
public class <ModMain>DataGenerator {
    @SubscribeEvent
    public static void gatherData(GatherDataEvent.Client event) {
        event.createProvider(ModRecipesProvider.Runner::new);
        event.createProvider(ModBlockTagsProvider::new);
        event.createProvider(ModItemTagsProvider::new);
        // ...更多 Provider
    }
}
```

## 配置管理

- 使用 NeoForge `ModConfigSpec` API
- 集中在一个 `Config` 类中定义
- 在 `@Mod` 构造方法中通过 `modContainer.registerConfig()` 注册
- 支持 `COMMON` / `CLIENT` / `SERVER` 三种配置类型

## 实体与生物生成架构

支持两种生物生成方式，可根据需求选择（详见具体设计文档）：

1. **Biome Modifier（群系自然生成）**：通过数据驱动向特定群系追加生成条目，受 mob cap 约束。适用于主世界通用怪物，代码量少，数据可覆盖。
2. **CustomSpawner（独立生成器）**：实现 `CustomSpawner` 接口，完全自主控制生成逻辑，不受 mob cap 约束。适用于需要特殊生成条件的生物（如时间、天气、结构关联等）。

## 模组入口类结构

`@Mod` 主类的构造方法是唯一注册入口，按以下顺序组织：

1. 注册 Mod 总线监听器（`commonSetup`）
2. 注册各类 `DeferredRegister`（物品 → 方块 → 物品栏 → 实体）
3. 注册 Game 总线监听器（`NeoForge.EVENT_BUS.register` / `addListener`）
4. 注册创造模式物品栏事件
5. 注册配置文件
